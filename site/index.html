The finish line

You're done when all five of these are true.

  • The front desk sees who is active and who is past due when a kid checks in.
  • Members, families, classes, attendance, levels, waivers and billing records live in The LAB's own app.
  • Staff open it from a link on their phones and sign in.
  • Every Spark record is exported and stored before Spark is cancelled.
  • The non-renewal notice reaches Spark at least 30 days before the term ends.

Setup

About 30 minutes, once.

Install

  • Claude Code, signed in. Use the VS Code extension if you'd rather not work in a terminal.
  • Node.js 22 or newer.
  • Git and a GitHub account.
  • VS Code.
  • An empty folder named lab-spark, opened in VS Code with the Claude Code panel open.

Ground rules

  • Never paste the Spark security key, passwords, card numbers or member details into a prompt.
  • Use clearly fake sample members until step 7 puts real data behind a sign-in.
  • Read each approval before you say yes. Take extra care with delete, push and send.
  • Pushing to main publishes the site. Do it on purpose.

Map Spark

1 hour · Claude does the reading

A written checklist turns "make it like Spark" into work you can tick off. Claude sends helper agents to read Spark's public pages and help center, then merges what they find into one table.

Type this

Prompt
Find screenshots, documentation and everything we'd need for parity with Spark Membership. Public sources only: sparkmembership.com, help.sparkmembership.com including the monthly release notes, and their YouTube tutorials. Write docs/spark-parity.md as a table: area, what Spark does, our plan, status. Keep screenshots in a gitignored folder. End with a short list of where we can beat Spark.

Then you decide

Mark each row must-have, later or skip. Skip what nobody uses. That decision is yours, not Claude's.

4

Put it on The LAB brand

1 hour

Tokens are named colors and sizes the whole app uses, such as "accent" instead of a hex code. Changing the brand later becomes one edit, and a lint (an automatic check) stops off-brand colors from getting in. The LAB app repo already has a brand kit and a design system, so point Claude at them.

Type this

Prompt
Set up a design system from The LAB brand kit in <path to lab-skill-unlocks>/brandkit and the rules in <path to lab-skill-unlocks>/app/DESIGN-SYSTEM.md. Navy #0F0E54, cyan #22BCED for actions, mint #C2E6DB for secondary actions, ink #090D19 for text, Argentum Sans headings and Work Sans body. Two token layers (brand colors, then names the UI uses), a component library, a style-guide page, and a lint that fails if any UI color is off the tokens.

7

Connect real data

A few sessions · needs accounts

Shared data across phones, real sign-ins, card payments and automatic texts all need a server. The LAB app (the lab-skill-unlocks repo) already has one, plus a Spark webhook that receives member status, past-due and join dates, check-in, and a consent log. Reuse it before building new.

Type this

Prompt
<path to lab-skill-unlocks> is our existing LAB app. It already has a Supabase backend, a Spark webhook, check-in and a consent log. Read it and tell me what we should reuse. Then plan how to move members, families, memberships and attendance onto it behind real sign-ins. Don't change that repo until I approve the plan.
Billing is the hard part

Recurring card and bank payments need a processor (Stripe or similar), a server and your accounts. Decide who bills before you build it: the new app, or another system. Ask Spark in writing whether stored cards can move to the new processor. If they can't, families re-enter cards.

8

Cut over and cancel Spark

Plan 45+ days ahead of the term end

This step is a checklist, not a prompt. Do it in this order.

  • Find the term end date in the Spark contract. Put the non-renewal deadline, 30 days before it, on the calendar.
  • While the account is still paid, export: All Contacts with every column, Past Due Memberships, each waiver and form's submissions (CSV), signed membership agreements, and attendance and rank history.
  • Ask Spark's data team in writing for a full archive. Don't count on the 30-day window after the contract ends.
  • Waivers: get an Arizona attorney to review the app's waiver text, and the insurance carrier's sign-off, before it replaces Spark's form.
  • Run both systems side by side for two weeks. Check that the active and past-due counts match each day.
  • Move billing, then send the non-renewal notice in writing.
Ask Claude to check the exports

Put the export files in a gitignored folder and ask: "Compare these Spark exports with the app's data and list every member, family or waiver that's missing." Real member data never goes in the public repo.

Habits that make it work

The Axis app was built in about two days with ten prompts. These habits did most of the work.

Say the outcome

"So the desk knows who's past due before class" beats a list of buttons. Describe the job from the user's side.

Give it the material

Paste folder paths, links and file names. Claude reads them directly.

Push back

"This feels basic. What do the best gyms use?" is the prompt that turned Axis from a toy into a product.

Say how you'll judge it

"Test it on live, not localhost" and "show me at phone size" catch bugs a summary hides.

State the standard

"Free, open source, just works" changed how Axis was designed. One sentence about what you value goes a long way.

Commit at every working step

Say "commit this" whenever something works. A commit is a checkpoint you can go back to.

When it goes wrong

Problems the Axis build ran into, and the fix for each.

The live site is blank, but local works

Usually the base path. Say: "The live site is blank. Check the base path and the 404 fallback for GitHub Pages, fix it, push, and test on live."

"node is not recognized" on Windows

Node isn't on the PATH. Reinstall Node from nodejs.org and restart VS Code, or tell Claude the error and let it fix the PATH for the session.

Buttons lost their colors

A long-running dev server can serve old styles. Say: "restart the dev server."

Claude says it's done and I'm not sure

Ask to see it: "Open every page at phone and desktop width, take screenshots, and show me any console errors." Read the screenshots yourself.

It keeps listing things it can't finish

Those rows need a server, accounts or your decision: payments, automatic texts, real sign-ins. Mark them "later" in the parity checklist, or do step 7.

The conversation got long and confused

Commit, then run /clear to start fresh. Claude rereads CLAUDE.md and the brief.

Commands worth knowing

/help lists commands. /init writes CLAUDE.md. /goal sets a finish line. /clear starts fresh. /code-review checks your changes for bugs before a big push.
